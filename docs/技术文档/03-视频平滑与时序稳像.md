# 03 视频平滑与时序稳像

## 1. 本步骤的位置

数据处理顺序应固定为：

```text
数据集载入
→ T0 时间对齐与修复
→ 视频平滑与时序稳像
→ S1-S5 质量清洗
→ C3 手部可见性判定
→ 关节流规范化与 MANO21 适配
→ 投影、标注与导出
```

因此，T0 之后的下一步确实是视频平滑。关节格式转换不应提前到视频平滑之前：格式转换解决的是“关节数、点序、坐标语义”，视频平滑解决的是“画面时序中的相机抖动和观感稳定性”，两者作用对象不同。

## 2. 目标与非目标

视频平滑只生成一个用于后续分析和审阅的派生 RGB 视频。原帧率模式保持帧数，高帧率 EIS 模式会建立新的均匀目标时间轴。它的目标是：

- 减少相机整体平移、旋转造成的画面抖动；
- 用轻度锐化改善压缩或缩放后的边缘观感；
- 保持原始时间语义和分辨率；若降至 30 FPS，则逐帧保存源帧位置，使 T0 映射、C3 帧号和导出帧号仍然可复现。

它不是：

- 不能恢复曝光期间已经丢失的细节；
- 不能把模糊的手部重新识别出来；
- 不能对 MANO/Nexus/OpenXR 关节坐标做平滑；
- 不能替代 T0，也不能改变深度、触觉或外参数据；
- 原帧率模式不做补帧、删帧或变速；高帧率 EIS 模式允许生成经审计的 30 FPS 派生时间轴。两种模式都不重建音频。

## 3. 输入门禁与模式边界

### 3.1 输入

入口从已确认的 `manifest` 和 Episode 选择参考媒体。调用平滑前会执行 T0 时间轴检查，确保参考视频和动态传感器的关系已经有可审计依据。平滑本身只读取 `modality=rgb` 且 `smoothing_eligible=true` 的媒体流。

Depth、IR、触觉和原始 HDF5/Parquet 关节流只能预览或参与各自的同步/适配流程，不能被当作视频平滑输入。

### 3.2 数据集模式

视频平滑不按点数猜测数据集格式，也不套用 Nexus 外参：

- EgoDex：平滑 EgoDex 的 RGB 参考视频；相机位姿仍来自 EgoDex 自己的 HDF5 语义；
- Nexus：平滑选定的 Nexus RGB 流；Nexus 外参只在之后的空间投影步骤使用；
- OpenXR：平滑 OpenXR 关联的 RGB 流；OpenXR 关节语义和相机模型在后续适配/投影步骤处理；
- 未知或冲突模式：允许视觉平滑（若 RGB 媒体通过门禁），但禁止借此推断关节格式或坐标空间。

## 4. 当前实现流程

当前实现位于 `app/video_smoothing.py::smooth_video()`。`native` 模式逐帧处理且不改变帧数；`eis_30` 模式执行双遍稳像并生成均匀目标时间轴。

### 4.1 有界运动分析

原始帧先按 `ALICE_VIDEO_ANALYSIS_MAX_SIDE`（默认 640）缩小为灰度分析图。缩小只用于估计运动，输出仍保持原始宽高，因此大视频不会因为特征跟踪而占用不受控的内存。

### 4.2 光流和全局运动估计

相邻帧之间使用以下链路估计相机整体运动：

```text
Shi-Tomasi 特征点
→ Lucas-Kanade 光流
→ 有效点筛选
→ RANSAC estimateAffinePartial2D
→ dx、dy、旋转角
```

只保留平移和旋转的部分仿射模型，不估计任意透视形变。特征点不足、光流失败或 RANSAC 无法拟合时，记录 `failed_motion_estimates`，该帧不引入新的运动量，并沿用已有轨迹状态。

### 4.3 轨迹平滑和画面变换

将相邻帧运动累加成相机轨迹。两种模式使用不同的轨迹处理：

- `native`：在线指数平滑，保持原帧率和原帧数；
- `eis_30`：第一遍完成整段运动估计，再执行前后向零相位平滑，避免单向滤波造成明显时延。

两种模式都根据平滑轨迹与原轨迹的差得到逐帧修正，并对平移和旋转设置上限。随后执行部分仿射变换，并叠加默认 `border_zoom=1.025` 的中心放大，以减少稳像后的反射边界。边界使用反射填充，不读取数据集外部像素。

### 4.4 轻度锐化

稳像后的画面经过一个 3×3 的高频增强核，默认 `sharpen_strength=0.32`。该步骤只改变像素观感，不改变关节数据、时间戳或 C3 的判定规则。

### 4.5 编码和加速

处理后优先尝试 FFmpeg 的 NVENC/QSV 编码；不可用时回退 OpenCV `mp4v`。像素处理可使用 CUDA，运动分析可使用 OpenCL；运行时失败会降级 CPU 并在 sidecar 中保留原因。GPU 设备由 `ALICE_GPU_DEVICES` 轮转选择，不能改变结果的帧语义。

## 5. 产物、应用和审计

每个 Episode 的非 Full 任务产物写入：

```text
<dataset>/.alicePD/video-smoothing/<episode>/
  <stream>.smoothed.mp4
  <stream>.smooth.alice
  <stream>.smooth.frames.npz  # 高帧率 EIS 逐帧审计
```

Full run 则写入该 run 的 `episodes/<episode>/smoothing/`，并将平滑产物、冻结的 `timeline_id` 和后续清洗产物一起登记。

sidecar 使用 `alice/video-smoothing/v3`，至少保存：

- 源媒体 `file_id`、流名和相对路径；
- 实际处理帧数、FPS、分辨率；
- 平均相机运动量、平均稳像修正量和失败估计次数；
- 运动分析分辨率、处理后端、编码器、GPU 和 CPU 回退原因；
- 平滑参数、锐化参数、边界放大和“无音频保留”声明；
- `change` 记录，用于人工审核后应用或撤销。

源视频始终只读。只有在 `video_smoothing` 更改记录被应用后，普通后续任务才会通过 `preferred_smoothed_media()` 使用这份派生视频；Full run 使用本次 run 内冻结的平滑产物，不引用其他 run 的结果。

## 6. 与 T0、S1-S5 和 C3 的关系

原帧率模式不重建时间轴，输出帧按源视频顺序写回。高帧率 EIS 模式显式生成 `source_frame_positions` 和逐帧审计文件，并已作为 Full Pipeline 的默认平滑模式；当源 FPS 不高于目标 FPS 时自动回退原帧率模式。由于某些 MP4 容器可能报告或保留物理尾帧，Full 的原帧率回退模式仍把分析帧数限制在“选定源媒体的逻辑帧数”和“平滑输出帧数”的较小值。

Full 流程中的顺序是：

```text
T0 验证参考媒体
→ 平滑生成 analysis_media
→ S1-S5 在 analysis_media 上清洗
→ C3 按同一逻辑帧号判定 MANO 点可见性
→ VLM/C1/C2/导出
```

C3 的质量规则仍然独立：全部 MANO 点可见为有效帧，部分可见为待复核帧，全部或超过 60% 不可见为坏帧。高帧率模式先通过 T0 把 Joint/State、触觉和已应用归正结果映射到分数源位置，再以平移线性插值和旋转 SLERP 重建 4×4 变换；C3 投影后继续叠加对应输出帧的 EIS 图像变换。平滑不会把“格式不匹配、T0 无映射、坐标系未转换”变成真实不可见，也不会覆盖坏帧标记。

## 7. 当前已知限制与下一步改进

当前实现是全局相机稳像，不是针对手部区域的运动补偿。手相对相机的真实运动会保留；前景和背景发生大面积独立运动时，全局仿射模型可能不稳定。原帧率兼容模式仍采用在线指数平滑且只保存统计摘要；高帧率 EIS 模式已经使用前后向离线平滑，并把逐帧变换写入压缩审计文件。

后续应按以下顺序改进：

1. 将高帧率模式已有的逐帧 `motion_valid`、`dx/dy/angle` 和修正矩阵审计扩展到原帧率兼容模式；
2. 对长时间光流失败、突发大修正和边界裁切生成明确 warning，而不是只记录总数；
3. 为 `native` 模式增加可选的离线前后向平滑，减少在线指数平滑的相位滞后；
4. 将可选机器人 Action 派生文件从“源帧率独立产物 + Full 中重映射校验掩码”升级为直接保存目标 30 Hz Action 时间轴；
5. 在稳定版本验证后，再进入 MANO21 关节流规范化；关节坐标平滑应作为独立模块，并保留原始坐标和滤波参数。

## 8. 高帧率 EIS 与 30 FPS 重采样

### 8.1 启用条件

`eis_30` 是电子稳像和时间重采样模式，不是光学防抖。独立“视频平滑”任务和 Full Pipeline 都可使用该模式，Full 默认选择它。

- 源 FPS 高于目标 FPS 至少 `0.25` 时，执行高帧率 EIS 和降采样；
- 源 FPS 不高于目标 FPS 时，自动回退 `native`，不补帧也不改变播放速度；
- 目标 FPS 默认 `30`，接口允许范围为 `1–60`；
- 源视频保持只读，输出始终写入 `.alicePD` 或 Full run 目录。

### 8.2 处理流程

高帧率模式执行两遍视频读取：

```text
第一遍：解码源帧和时间戳
→ 估计相邻帧全局运动
→ 累积相机轨迹
→ 前后向零相位平滑
→ 生成每个源帧的稳像矩阵

第二遍：逐源帧执行稳像
→ 按均匀目标时间轴定位左右源帧
→ 非整数位置执行双向稠密光流插值
→ 低置信度或光流失败时回退真实稳像源帧
→ 编码目标 FPS 视频
```

目标时间轴优先使用解码得到的 OpenCV PTS 证据；时间戳不可用或不可靠时，回退 `frame_index / source_fps`。每个目标帧都会保存对应的连续源帧位置，而不是只保存一个取整帧号。

### 8.3 逐帧审计

`<stream>.smooth.frames.npz` 保存：

```text
source_timestamps
target_timestamps
source_frame_positions
target_left_frames
target_right_frames
interpolation_alpha
synthetic_mask
flow_confidence
fallback_code
source_motion
source_motion_valid
source_motion_confidence
source_stabilization_matrices
target_stabilization_matrices
source_stabilization_correction
```

`synthetic_mask` 表示目标帧是否位于两个源帧之间；`fallback_code` 记录关闭运动补偿、低置信度、光流错误、缺少相邻帧或分辨率限制等回退原因。回退不会静默发生。

### 8.4 下游时间重映射

Full 使用 `source_frame_positions` 把目标视频帧映射回 T0 原始视频时间轴，再取得各传感器的分数行位置：

- 普通数值流使用连续位置插值；
- 4×4 位姿使用平移线性插值和旋转 SLERP；
- 两侧任一同步锚点无效时，目标帧保持无效，不能由视觉合成掩盖；
- 坏帧、VLM 区间、S1-S5/C3 结果均使用目标视频帧号。

可选机器人 Action 文件目前仍是源帧率派生产物；Full 会把它的 S2 校验掩码映射到目标时间轴，但尚未另写一份 30 Hz Action 文件。

### 8.5 相机几何与导出

每个目标帧保存从源图像像素到稳像图像像素的 3×3 变换 `H_frame`。C3 和 Joint Overlay 先按源相机模型投影，再执行：

```text
pixel_output = H_frame @ pixel_source
```

LeRobot 每帧保存：

- `observation.camera.image_transform`；
- `observation.camera.intrinsic = H_frame @ K_source`；
- `source.video_frame_position`；
- `source.hdf5_position`。

HDF5 兼容导出对应保存 `camera/image_transform`、逐帧 `camera/intrinsic`、`source_video_frame_position` 和 `source_hdf5_position`。

### 8.6 实现边界

- 当前只估计全局平移和旋转，不使用 IMU，也不估计任意透视变换；
- 双向稠密光流只用于生成非整数时间位置的图像，置信度不足时回退真实帧；
- `H_frame` 描述全局 EIS 变换，不能表示合成帧中每个动态物体的局部光流；
- 没有实现多帧曝光积分或所谓“时间超采样”；
- 超高分辨率导致稠密光流内存风险时，自动回退真实稳像源帧。
